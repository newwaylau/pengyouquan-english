Critical Layout Defect
urgent #1 Action Buttons: white-space: nowrap Causes English Text Overflow
Location: Practice page — action button row (提交 / 剧集原音 / 下一句 / 显示中文 / 显示英文)
Root Cause: The .action-btn and .btn-speed classes set white-space: nowrap, preventing text from wrapping when container width shrinks. Combined with flex: 1 1 0%, buttons share available width equally, but English text (typically 2-3× longer than Chinese equivalent) exceeds the allocated width.
/* Current CSS — root font-size: 28px (desktop), ~22.75px button text */
.action-btn {
  flex: 1 1 0%;
  padding: 11px;
  font-size: 0.8125rem; /* ~22.75px @ 28px root */
  white-space: nowrap; /* ← OVERFLOWS on long English */
}

Recommendation:
  1. Remove white-space: nowrap from .action-btn — let text naturally wrap. Add word-break: break-word; hyphens: auto for graceful truncation.
  2. Add min-width: 0; overflow: hidden; text-overflow: ellipsis as a safety net.
  3. For icon+text buttons (.action-btn with gap: 6px): increase horizontal padding or set flex-shrink: 0 on the icon to prevent icon compression.

high #3 Sidebar Nav Icons + Text: Stacking in Narrow Sidebar
Location: Desktop sidebar navigation — 练习, 错题本, 搜索, 浏览
Root Cause: Sidebar is 220px wide (desktop). Buttons have flex-direction: row with icon + label. At 220px, the Chinese text fits comfortably. However, when the sidebar width shrinks (tablet / narrow desktop), English labels like "Wrong Book" or "Practice" will compete for space with icons.
.sidebar-nav-item {
  width: 220px;
  padding: 12px 16px;
  font-size: 0.8125rem; /* ~22.75px @ 28px root */
}
.sidebar-nav-label {
  white-space: nowrap; /* ← same overflow risk */
}
Recommendation: For the sidebar, English labels like "Practice" (8 chars) and "Wrong Book" (10 chars) will fit at 220px. The main risk is at tablet breakpoints (768px) where the sidebar may collapse. Consider using overflow: hidden; text-overflow: ellipsis or switching to icon-only mode below 768px.
medium #4 Speed Button Row: Tight Horizontal Padding
Location: Playback speed buttons — 0.5x, 0.75x, 1x, 1.5x
Root Cause: .btn-speed has padding: 0.375rem 0.625rem (~6px 10px). While speed values (0.5x, 1x) are short and unaffected, if these buttons ever carry longer labels in English mode (e.g., "Slow", "Normal", "Fast"), they will overflow. Current labels are safe.
.btn-speed {
  flex: 1 1 0%;
  min-width: 0;
  padding: 0.375rem 0.625rem;
  font-size: 0.8125rem;
}
Recommendation: Add white-space: nowrap; overflow: hidden. Currently low risk but good practice for future-proofing. Also consider min-width: 48px for touch target compliance.
medium #5 Login/Register Button: Full Width Safe, But Long Translation Risk
Location: Login page — submit button ("登录")
Root Cause: The login submit button uses width: 100%; padding: 11px. With full container width available, "Login" / "Submit" / "Sign In" would all fit. However, if a longer phrase like "SIGN IN TO CONTINUE" or "VERIFY EMAIL" is used, it could overflow. Currently lower risk.
.login-form-container .submit-btn {
  width: 100%;
  padding: 11px;
  font-size: var(--text-aux); /* 0.8125rem */
  font-family: inherit;
}
Recommendation: Add white-space: nowrap; overflow: hidden; text-overflow: ellipsis as a safety net. Consider a maximum text length validation or responsive font sizing for the button text.

🔧 System-Wide Recommendations

1. Root Font Size Considerations

Root font-size: 28px is set on the <html> element. This means 0.8125rem = 22.75px button text, which is quite large. For mobile 375px viewport, this creates very limited character real estate.
Recommendation: Consider setting root font-size proportional to viewport width using clamp():
html { font-size: clamp(16px, 4.375vw, 28px); }
This would give 16px on a 375px phone, ~22px on tablet, and 28px on desktop, ensuring buttons have enough room on mobile.

2. Touch Target Sizing

Multiple buttons have padding that produces touch targets smaller than the recommended 44×44pt (Apple HIG) / 48×48px (Material Design). Specifically:
  • .btn-speed — padding: 6px 10px → total height ~34px at 22.75px font
  • .bottom-nav-btn — padding: 6px 4px → very tight

3. No Internationalization (i18n) System Detected

All UI labels in the JS bundle are hardcoded as Chinese strings. There is no i18n / translations dictionary in the bundle. To properly support English mode, the app would need:
  • A translation dictionary mapping Chinese → English for every UI string
  • A language toggle (URL param, localStorage, or settings page)
  • Responsive button widths that accommodate 2-3× text expansion
