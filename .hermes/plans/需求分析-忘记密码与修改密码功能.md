# 需求分析：忘记密码 + 修改密码功能

## 一、背景

用户目前支持邮箱+密码注册/登录，已有发送验证码接口（`POST /api/auth/send-code`）和验证码校验能力（`EmailCodeService.verifyCode`）。但缺少以下两个功能：

1. **忘记密码**——用户无法自行重置密码
2. **修改密码**——登录用户无法修改自己的密码
3. 管理员 newwaylau@hotmail.com 已忘记密码，需要一并解决

## 三、功能一：忘记密码

### 3.1 流程

```
登录页 → 点击"忘记密码"链接 → 输入邮箱 → 发送验证码 → 输入验证码 + 新密码 → 重置成功 → 自动登录
```

### 3.2 后端新增

#### 3.2.1 复用或新增发送验证码接口

现有 `POST /api/auth/send-code` 只是发送验证码到邮箱，**不检查邮箱是否存在**。注册时前端自己校验邮箱未注册，但忘记密码需要**检查邮箱已注册**。

**方案 A（推荐）**：创建新端点
- `POST /api/auth/forgot-password/send-code`
  - Request: `{ email }`
  - 逻辑：检查用户是否存在 → 若不存在则返回错误 "该邮箱未注册" → 若存在则发送验证码
  - 响应：`ApiResponse.success(null)` 或 `ApiResponse.error("该邮箱未注册")`

**方案 B**：给现有 `/api/auth/send-code` 加可选参数增加 `type` 字段
- 需要改前端已有注册逻辑，风险稍高。推荐方案 A 保持向后兼容。

#### 3.2.2 重置密码接口

- `POST /api/auth/reset-password`
  - Request: `{ email, code, password }`
  - 逻辑：
    1. 校验邮箱验证码（复用 `EmailCodeService.verifyCode(email, code)`）
    2. 检查用户是否存在（`UserRepository.findByEmail(email)`）
    3. 更新密码（BCrypt 编码后保存）
  - 响应：`LoginResponse`（包含新 JWT Token，让用户自动登录）

### 3.3 前端修改

#### 3.3.1 LoginPage.tsx 修改

- 当前 `mode` 为 `'login' | 'register'`
- 扩展为 `'login' | 'register' | 'forgot'`

**登录模式下：**
- 在密码输入框下方增加"忘记密码？"链接
- 点击后切换到 `mode='forgot'`

**忘记密码模式（mode='forgot'）：**

步骤 1 — 输入邮箱:
- 只显示邮箱输入框 + "发送验证码"按钮
- 发送成功后进入步骤 2

步骤 2 — 重置密码:
- 显示验证码输入框（复用已有 code-row 样式）
- 显示新密码输入框 + 确认密码输入框
- 密码强度要求同注册（至少8位，字母+数字）
- 提交按钮"重置密码"
- 成功后自动登录（类似注册行为）

**切换逻辑：**
- 底部增加"返回登录"链接

#### 3.3.2 api/client.ts 新增

```typescript
// 忘记密码
forgotPasswordSendCode: (email: string) =>
  request('/api/auth/forgot-password/send-code', { method: 'POST', body: JSON.stringify({ email }) }),
resetPassword: (data: { email: string; code: string; password: string }) =>
  request('/api/auth/reset-password', { method: 'POST', body: JSON.stringify(data) }),
```

### 3.4 涉及的文件

| 文件 | 操作 |
|------|------|
| `AuthController.java` | 新增 2 个端点 |
| `AuthService.java` | 新增 `forgotPasswordSendCode()`, `resetPassword()` 方法 |
| DTO 新增 | `ResetPasswordRequest.java`, `SendCodeRequest`（已存在，可复用） |
| `LoginPage.tsx` | 新增 forgot 模式 |
| `api/client.ts` | 新增 2 个 API 方法 |

## 四、功能二：修改密码

### 4.1 流程

```
用户已登录 → 打开个人设置 → 修改密码 → 输入旧密码 + 新密码 + 确认新密码 → 提交 → 密码更新成功 → 重新登录(可选)
```

### 4.2 后端新增

#### 4.2.1 修改密码接口

- `PUT /api/auth/password`
  - 需要 JWT 认证（`@CurrentUserId`）
  - Request: `{ oldPassword, newPassword }`
  - 逻辑：
    1. 通过 `@CurrentUserId` 获取用户 ID
    2. 查询用户
    3. 校验旧密码（`passwordEncoder.matches(oldPassword, user.getPassword())`）
    4. 校验新密码强度（至少6位，建议8位+字母+数字）
    5. 更新密码（BCrypt 编码）
  - 响应：`ApiResponse.success(null)`

#### 4.2.2 DTO

```java
public class UpdatePasswordRequest {
    @NotBlank
    private String oldPassword;
    @NotBlank @Size(min = 6, max = 50)
    private String newPassword;
}
```

### 4.3 前端修改

**不放在 SettingsPanel 中**（SettingsPanel 是练习设置，不是个人账号设置）。

建议两种方案：

**方案 A（推荐）：放在 LoginPage 顶部导航的用户区域**
- 在 App.tsx 的顶部导航栏，用户已登录时显示 `{user.nickname}` + "退出"按钮
- 增加一个"个人设置"或直接在 PracticePage 底部导航增加一个"账户"入口
- 或者，在顶部导航点击用户昵称时，弹出一个下拉菜单包含"修改密码"

**方案 B：独立账户页面（AccountPage.tsx）**
- 新增页面组件，包含修改密码、修改昵称等
- 在 App.tsx 路由中增加 `'account'` 页面类型
- 更干净，但改动更大

**推荐方案 A 的简化实现：**
- 在 SettingsPanel 底部增加一个"账户安全"区块，包含"修改密码"
- 或者直接在顶部导航栏增加"修改密码"入口（最简单）

#### 4.3.1 最小实现方案

**修改 SettingsPanel.tsx：**
- 在底部增加"账户"区域，包含"修改密码"按钮
- 点击后弹出修改密码表单（内联在 SettingsPanel 内或弹出新面板）

**或修改 App.tsx 顶部导航：**
- 用户已登录时，在用户昵称旁增加"设置"下拉
- 包含"修改密码"选项
- 点击后直接在当前页面弹窗

**推荐的最终方案——在 SettingsPanel 底部添加"账户安全"区域：**
- 对用户改动最小，用户已习惯在 SettingsPanel 中做所有设置
- 修改密码成功后可选：提示重新登录（JWT 无需重新生成，但可以提示）

#### 4.3.2 api/client.ts 新增

```typescript
updatePassword: (data: { oldPassword: string; newPassword: string }) =>
  request('/api/auth/password', { method: 'PUT', body: JSON.stringify(data) }),
```

## 五、管理员密码重置

管理员 newwaylau@hotmail.com 忘记密码，可通过以下方式解决：

**方式 A（推荐）：通过忘记密码功能自行重置**
- 登陆页点击"忘记密码" → 输入 newwaylau@hotmail.com → 接收验证码 → 重置密码
- 需要邮件服务能正常发送到 hotmail（已有配置使用 newwaylau@163.com 发送）

**方式 B（兜底——直接 SQL）：**
```sql
UPDATE users SET password = '$2a$10$...BCrypt_hash...' WHERE email = 'newwaylau@hotmail.com';
```
需手动生成 BCrypt 密码哈希。不推荐作为常规方案。

**建议：功能上线后，管理员通过忘记密码流程自行重置即可。**

## 六、API 汇总

| 方法 | 路径 | 认证 | 说明 |
|------|------|------|------|
| POST | `/api/auth/forgot-password/send-code` | 无 | 忘记密码发送验证码（检查邮箱已注册） |
| POST | `/api/auth/reset-password` | 无 | 重置密码（验证码 + 新密码） |
| PUT | `/api/auth/password` | JWT | 修改密码（旧密码 + 新密码） |

## 七、开发顺序建议

1. 后端：`forgot-password/send-code` + `reset-password` 接口和 Service 逻辑
2. 前端：LoginPage 扩展 forgot 模式
3. 后端：`PUT /api/auth/password` 接口
4. 前端：SettingsPanel 增加修改密码
5. 管理员密码重置（功能上线后自行操作）
6. 测试

## 八、注意事项

1. **发送验证码频率**：现有 `/api/auth/send-code` 无频率限制，新增接口也应暂时保持相同策略（后续可加）
2. **密码强度**：重置密码和修改密码的密码强度应和注册一致（至少8位，含字母和数字）
3. **用户不存在错误**：`forgot-password/send-code` 返回 "该邮箱未注册"，不暴露注册邮箱列表
4. **验证码复用**：忘记密码和注册共用同一个 email_codes 表，验证码校验逻辑一致（5分钟有效期，使用后删除）
5. **旧密码校验**：修改密码时校验旧密码是否正确，防止未授权修改
6. **JWT 有效期**：首次实现不需要在修改密码后强制重新登录（JWT 无状态，新密码只在下次登录使用）
