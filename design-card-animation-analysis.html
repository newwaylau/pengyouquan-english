# 卡牌动画 + 杀戮尖塔兼容性分析 ## 一、当前卡牌系统 vs 杀戮尖塔兼容性 ### 表结构检查 ✅ 基本兼容 | 列名 | 当前值 | 杀戮尖塔需求 | 兼容？ | |------|--------|-------------|-------| | `card_type` | minion/spell/equipment/location | attack/skill/power/curse/status | ⚠️ 类型名称不同，需要映射 | | `cost` | 1-8 | 0-3 energy | ✅ 数值通用 | | `attack` | 0-8 | damage per card | ✅ | | `health` | 1-8 | 不适用（HP是战斗状态） | ✅ | | `effect_json` | JSON描述 | 结构化效果数据 | ⚠️ 需要新增结构化字段 | | `keywords` | battlecry/taunt等 | 无直接对应 | ✅ StS无关键词系统 | | `faction` | stark/targaryen | 种族faction | ✅ 可用于事件触发 | | `race` | 龙/人/兽 | 无直接对应 | ✅ 可用于动画 | | `element` | 火/冰/暗影 | 无直接对应 | ✅ 可用于动画 | ### 实际兼容性问题 **1. 卡牌类型映射** ``` minion → attack（造成伤害的随从卡） → skill（提供格挡/效果的随从卡） spell → skill（法术效果） → power（持续能力） equipment → power（装备效果） location → power（场地效果） ``` **2. 效果数据 → StS需要结构化** 当前 `effect_json` 是自由文本描述： ```json {"description_cn": "召唤一个 2/2 的冰原狼", "description_en": "Summon a 2/2 Direwolf"} ``` StS需要： ```json { "damage": 6, "block": 5, "buff_self": {"strength": 1}, "debuff_enemy": {"vulnerable": 2}, "draw": 1, "description_cn": "造成 6 点伤害，获得 5 点格挡" } ``` **3. 费用不对等** 现有卡牌费用较高（1-8），StS费用低（0-3）。 → StS模式下可对费用做缩放：cost/2 或保持大费用+高能量 ### 结论 ✅ **数据结构完全兼容** — race/element/keywords/rarity 字段都已存在 ✅ **可以直接用现有卡牌打StS战斗** — 只需添加 effect_structured 字段 ⚠️ **现有卡牌缺少StS战斗数据** — 需要为每张卡补充 damage/block/buff 参数 --- ## 二、卡牌动画系统设计 ### 核心架构：4参数引擎 ``` 每张卡 → race + element +
